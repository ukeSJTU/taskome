# Integrations

This page covers the external systems Taskome calls or receives calls from — the ones [`containers.md`](./containers.md)'s diagram places outside the Taskome box — and what happens when a call to one of them fails. It does not repeat what already has a home elsewhere: [`security.md`](./security.md) owns exactly what data each external system may receive, and [`runtime.md`](./runtime.md) owns failure handling for Temporal and Kubernetes specifically, since both already have detailed sections there.

> **Target architecture, not shipped code.** None of these integrations are implemented yet. This page describes the accepted design they must follow once built.

## External systems

| System                     | What Taskome sends                                                                                                                                                                                                                                      | What Taskome receives                                               | Failure handling                                                                                                                                                                                                                                                                                                                                                                 |
| -------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **Temporal Service**       | Workflow and Activity payloads — identifiers, parameters, and file references, never scientific file contents (see [`overview.md`](./overview.md))                                                                                                      | Workflow and Activity task deliveries, timers, and recovery signals | An unreachable Temporal Service never blocks Job acceptance — the transactional outbox absorbs it (see [`runtime.md`](./runtime.md)). The Execution Service treats a failed call to Temporal as transient and retries, the same way it treats an unclear Kubernetes API response (see [`runtime.md`](./runtime.md)'s "Treat unclear scheduler state as unresolved, not failed"). |
| **Observability Backend**  | Correlation identifiers, operation names, timings, status, and deliberately selected non-sensitive metadata, currently as structured logs (see [`../engineering/observability.md`](../engineering/observability.md) and [`security.md`](./security.md)) | Nothing — this is a one-way export                                  | An export failure must never block the request or operation it was observing. Telemetry is a side channel, never a gate on product behavior.                                                                                                                                                                                                                                     |
| **Email Delivery Service** | Recipient address and message data needed for verification, recovery, or notification (see [`security.md`](./security.md))                                                                                                                              | Delivery status, where the provider reports it                      | A failed send must not silently mark a verification or recovery flow as complete. The retry policy and user-facing failure behavior for a failed send are not yet decided.                                                                                                                                                                                                       |
| **AI Model Provider**      | The minimum user-authorized context needed for the current Assistant operation (see [`security.md`](./security.md))                                                                                                                                     | Model inference output for the Agent Assistant                      | The Agent Assistant specification, not this page, owns behavior when an inference call fails or degrades.                                                                                                                                                                                                                                                                        |

## Why these are external, not containers

[`containers.md`](./containers.md) keeps the Temporal Service outside the Taskome box specifically to leave its hosting model visibly unresolved — a managed Temporal Cloud service and a self-hosted Temporal Service are different trust boundaries even though the application responsibilities the diagram shows don't change either way. The Observability Backend, Email Delivery Service, and AI Model Provider are external by nature: none of them hold Taskome domain state, and none of them are containers Taskome operates.

## Resolve implementation decisions in the owning section

- Temporal Cloud or a self-hosted Temporal Service — [`containers.md`](./containers.md).
- The Observability Backend product, and whether and when to adopt OpenTelemetry — [`../engineering/observability.md`](../engineering/observability.md).
- The Email Delivery Service product, and how local development avoids delivering real email — not yet decided by any page.
- The AI Model Provider selection, and the Agent Assistant's confirmation and degraded-service behavior — deferred to the Agent Assistant specification (see [`security.md`](./security.md)).
