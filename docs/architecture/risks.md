# Risks and technical debt

Known places where this architecture is thin, coupled, or carries a trade-off that persists even once the target design is fully built — not a tracker for what simply isn't built yet. Every accepted architecture page already marks its own open decisions under "Resolve implementation decisions in the owning section"; this page is for risk that remains real _after_ those decisions are made, not a duplicate of them.

| Risk                                                                                                      | Why it matters                                                                                                                                                                                                                                                                                                                                                     | Status / mitigation                                                                                                                                                                                                             |
| --------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| A small, fixed GPU fleet has no fairness or priority policy across users                                  | Kubernetes's default scheduler bin-packs available resources; it doesn't guarantee fair-share. One user submitting many long-running Jobs for the same Tool can queue every other user's Jobs behind them, and nothing in the accepted design prevents it.                                                                                                         | Open. [`requirements.md`](../product/requirements.md) sets no numeric queue-wait or throughput target, so this isn't a violated requirement today — but it's a real user-visible risk once more than one user shares the fleet. |
| Kubernetes's own Job retry must be deliberately disabled                                                  | [`containers.md`](./containers.md) requires that Kubernetes's `backoffLimit` never cause a Tool Runtime to execute twice for one Attempt — but that's a per-Job-spec setting, not something Kubernetes enforces on Taskome's behalf. A Job spec that leaves the default in place silently repeats scientific compute under one Attempt the first time a Pod fails. | Open. No test or validation described anywhere yet catches a Job spec that gets this wrong.                                                                                                                                     |
| The Execution Service (TypeScript) and Tool Runtimes (Python) share a manifest format with no shared code | [`components/tool-runtime.md`](./components/tool-runtime.md) treats the Invocation/Result/manifest contract as a schema both sides implement independently. Nothing currently checks the two implementations against each other — they can drift silently until an Attempt fails validation in production.                                                         | Open. [`components/tool-runtime.md`](./components/tool-runtime.md) tracks defining the schema's source of truth, but not yet a cross-language conformance check.                                                                |
| PostgreSQL and Object Storage have no shared transaction                                                  | [`data.md`](./data.md) already treats this as a structural fact, not a bug — staging bytes without committed metadata, or committed metadata whose bytes are missing, are both real states the design must reconcile, not eliminate.                                                                                                                               | Accepted as structural. [`data.md`](./data.md) owns the reconciliation rules; no detection or cleanup schedule exists yet.                                                                                                      |
| A non-highly-available Kubernetes control plane pauses new submissions during an outage                   | [`deployment.md`](./deployment.md) allows this trade-off deliberately for a small, fixed fleet rather than dedicating machines to control-plane high availability. It's a real availability cost whichever way an environment decides it.                                                                                                                          | Accepted as a deliberate option, not a default. [`deployment.md`](./deployment.md) owns the decision per environment.                                                                                                           |
| No documented backup, restore, or numeric recovery objective for PostgreSQL or Object Storage             | Data loss or extended downtime has no documented recovery path today.                                                                                                                                                                                                                                                                                              | Open — [`data.md`](./data.md) already lists this among its own unresolved choices.                                                                                                                                              |
| Pipeline chaining, multi-tenancy, training Tools, and payments are deliberately undesigned                | Building toward any of these without a settled design risks premature coupling if they're guessed at instead of designed when actually picked up.                                                                                                                                                                                                                  | Tracked in [`docs/product/vision.md`](../product/vision.md)'s Future direction — deliberately undesigned, not forgotten.                                                                                                        |
