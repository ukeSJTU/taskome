# Risks and technical debt

Known places where this architecture is thin, coupled, or deliberately unfinished — not a status tracker for what's simply not built yet (that's what the `> Status note` callouts scattered through the other architecture pages are for). This page is about risk that persists even once the target design is fully built.

| Risk                                                                                                                                                                                          | Why it matters                                                                                                                                                                                                                   | Status / mitigation                                                                                                                                                                                                        |
| --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Gateway is one service doing identity resolution, REST/MCP aggregation, Job queueing, dispatch, and Ray resource brokering                                                                    | A single service carrying this many responsibilities has a wide blast radius — an issue in any one of them can take down the others too.                                                                                         | Accepted for v1 as a deliberate simplification; see [`containers.md`](./containers.md)'s Job execution section for the planned split into an independent scheduler once it's warranted.                                    |
| Gateway → Task Server dispatch has no queue protection                                                                                                                                        | If Gateway's own worker process dies mid-call, a successfully completed Job's result is lost — the caller has to resubmit.                                                                                                       | Accepted for v1 given the small, trusted user base and this architecture's deliberately low availability priority (see [`overview.md`](./overview.md)). See [`integrations.md`](./integrations.md) for the full trade-off. |
| Task Servers' single-process/single-replica constraint rests on SeaweedFS's S3 conditional-write support, which is still evolving and inconsistent across the S3-compatible storage ecosystem | A constraint meant to be temporary is anchored to a feature outside Taskome's control that other storage backends (MinIO, at least) don't implement compatibly either — swapping storage doesn't cleanly remove this constraint. | Open. A more robust fix would move the non-overwrite guarantee to Postgres instead of leaning on storage-layer support — not yet designed.                                                                                 |
| One Postgres instance, no documented backup or high-availability story                                                                                                                        | Data loss or extended downtime has no documented recovery path today.                                                                                                                                                            | Open — not yet addressed by any doc in this tree.                                                                                                                                                                          |
| `docs/architecture/components/` is intentionally empty                                                                                                                                        | This restructuring stopped at C4 Context + Container; no Component-level diagrams exist for any container yet.                                                                                                                   | Deliberate scope limit for this pass, not an oversight.                                                                                                                                                                    |
| Personal API Keys never expire                                                                                                                                                                | A leaked key stays valid until someone notices and revokes it — there's no default TTL to bound the exposure window.                                                                                                             | Open — see [`security.md`](./security.md).                                                                                                                                                                                 |
| Deliberately deferred: job chaining, multi-tenancy, payment/credits, deeper Ray scheduling                                                                                                    | None of these block v1, but building toward them without a settled design risks premature coupling if they're guessed at instead of designed when picked up.                                                                     | Tracked in [`docs/product/vision.md`](../product/vision.md)'s Future section — deliberately undesigned, not forgotten.                                                                                                     |

## Scope limitation: `docs/research/` audit findings aren't folded in yet

`docs/research/` holds several architecture audit notes (`audit-gateway-architecture.md`, `audit-packages-architecture.md`, `audit-web-architecture.md`, and others) written before this documentation restructuring. Whatever risks or debt those audits identified are **not** reflected in the table above — folding them in is explicitly out of scope for this pass. A future pass should read `docs/research/*.md` and merge anything still relevant into this page, then decide whether the source audit notes stay or retire.
